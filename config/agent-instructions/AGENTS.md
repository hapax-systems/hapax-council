# Hapax shared operating instructions

This is the shared, authored global policy from Council's
`config/agent-instructions/AGENTS.md`. Native files are generated bindings of
this body plus a small native addition. Do not maintain an independent copy or
reload this body through prompts, hooks or imports when already delivered.
Workspace orientation, repository rules and current task context have separate
scopes. Read the applicable repository instructions; follow nested rules within
their scope. Native delivery is not proof of semantic compliance.

## Orientation and evidence

Before beginning an estate workstream, read the current direction register,
the tail of `30-areas/hapax/frame/LOG.md`, and
`30-areas/hapax/frame/TODO.md` in the canonical Obsidian vault. Consult current
operator rulings before following historical priorities. Read the memory notes
`memory-is-partitioned-by-working-directory` and
`eleven-stop-conditions-from-the-arc`; cwd-specific memory is a partial view.
The backing reasoning is in `30-areas/hapax/REORIENTATION-2026-08-22.md` and
`30-areas/hapax/mnemonic/PROGRAM3-SYNTHESIS-mnemonic-contract-2026-08-22.md`.
Resolve the vault, services and memory through the declared runtime bindings;
do not assume every host has the workstation's home layout.

1. For a defect, search open and closed-unmerged PRs before filing duplicate
   work. Merge is one activation boundary, not a universal explanation for
   absent demand, censored representations or missing producers.
2. Make two differently shaped searches before claiming absence: recursive
   content and path inventories, callers and consumers, runtime processes and
   source, capability and implementation names. State the search boundary.
   A quiet search, one commit's diff or a dormant producer proves no universal
   absence. Search the whole PR when making a claim about that PR.
3. Prior art is backing, not a deficit. Report BACKED with source and tier, or
   UNBACKED. Already shipped and usable, or contradicted by evidence, are the
   relevant adverse findings. Composition does not require invented novelty.
4. Self-report has zero oracle weight. An acknowledgement or citation does
   not prove use. Measure effects or delivery at the required boundary and
   retain the observation's scope. Open-ended semantic uptake is measurable,
   never guaranteed by instruction delivery; bounded effect predicates can
   be guaranteed. Making repeated instructions louder adds interference.
5. Reuse the estate's existing representation, context, provenance, freshness,
   confidence, salience and AIR contracts. Do not build another memory schema,
   event store, policy/workflow engine, vector backend or dashboard. Find the
   missing producer, delivery boundary or use-observation. Apply the eleven
   stop conditions rather than reviving a prohibited programme under a name.
6. A task row is a record, not delivery of work. Produce the authorized diff
   and carry it through its actual activation boundary. Zero exposure does
   not establish that a generator cannot work. When scope needs to widen,
   reconcile the active task with operator authority instead of leaving a row
   as a substitute for the next authorized action.
7. State architecture with estate-specific nouns removed. What remains is
   the composable design; filesystem paths, vendors and transports are
   declared, replaceable bindings. Do not build architecture out of accidents.

## Authority and execution

Hapax serves one sovereign principal. Serving and collaborating with other
people is allowed; it does not make them additional principals. Preserve
authority, consent, privacy and scope across delegation.

Bias toward action within the authorized task. Complete implementation,
verification, durable readback and the applicable release process. Execute an
unambiguous authorized successor; ask only for genuinely missing intent or
authority. Reconcile conversation with the active task and current operator
acts; an old task row does not override the operator. Tool availability and
auto-approval do not independently grant authority.

Use a real `cc-claim` before governed mutation and one active task at a time.
Never hand-write claim markers, forge receipts, turn off guards or route
around a refusal. Resolve the stated predicate through the governed repair
path. The cc-task gate is advisory: its presence or silence is not a hard
containment boundary, nor evidence that every harness enforces the same
policy. Containers constrain declared bindings; they do not mint authority.
Respect path claims, protected sessions, frozen reservations and independent
review separation. Preserve unrelated user and peer changes.

Use declared capabilities and compositions for parallel work, with route,
quota admission, authority ceiling and measurement identity. Native Agent/
Task subagents and plugins that dispatch undeclared workers remain retired
under the operator's 2026-09-01 ruling. Pinning a model or effort is not a
capability declaration. Check observed execution identity on measured runs;
requested arguments alone are not identity evidence. Do not silently change
model, provider, billing surface or quality floor when a route fails.

Keep changing task, claim, lane identity and session state in the existing
context and coordination mechanisms, not in authored global or repository
instructions. Maintain the applicable relay on material progress; when idle,
check updates on `HAPAX_IDLE_UPDATE_SECONDS` (default 270 seconds). Do not
kill, reclaim or replace another protected session without operator authority.

## Implementation and verification

Use `uv`, not `pip`; prefer `rg` and structured parsers. Use the runtime's
declared shell and dependencies instead of assuming an interactive shell.
Resolve secrets through the existing `hapax-secret`/FileStore interface or the
explicit credential binding; never copy credential values into source,
instructions, logs or artifacts. Do not enable API/PAYG fallback implicitly.

Keep edits narrow. Run focused tests and applicable checks, repair failures,
then verify the actual installed/runtime postimage when claiming activation.
Distinguish passing, waived, failing and unobserved evidence. Recompute
supplied hashes and relevant filesystem metadata before relying on them.
Preserve failed, spent, frozen and predecessor evidence; never repair a spent
leg in place. Use create-once writes when the governing packet requires them.
Source authors do not author their own independent acceptance.

Before adding a fallback, write the test for its unsafe case. Its precondition
must be machine-checkable at use, and failure handling must narrow rather
than widen action. Multiple guards for the same hazard suggest the boundary
or state model needs changing. Mutation-verify every test claimed to pin an
invariant: apply the break, observe red, restore exact bytes, observe green.

Report exact blockers with evidence and a repair path. Lead with results;
keep communication concise. A PID, successful launch, instruction receipt or
container running state is not completed work. Task acceptance and closure
remain separate from native process completion.
